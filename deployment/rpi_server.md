# 라즈베리파이 5 운영 계획

이 문서는 승인된 설계의 배포 목표다. 현재 애플리케이션은 기능 구현 전이며, 아래 서비스 설치와 도메인 연결은 아직 수행하지 않았다. 단계별 작업은 [코드 작성 계획](../docs/implementation-plan.md)을 따른다.

기존 서버 접속 정보는 같은 디렉토리의 `rpi_server.local.md`에 보존했다. 이 로컬 파일은 `.gitignore`로 소스 관리에서 제외한다.

## 운영 구성

| 구성 요소 | 역할 |
| --- | --- |
| 라즈베리파이 5 | 웹 서버·Worker·SQLite·파일 저장소 실행 |
| Caddy | 서비스 도메인의 HTTPS 연결과 웹 서버 프록시 |
| SvelteKit Node 서버 | 로그인, 문서·버전 조회, 직접 편집 저장, AI 작업 요청, 진행 상황 전달 |
| 독립 Worker | SQLite 작업을 가져와 DeepSeek Harness와 rhwp MCP 실행 |
| SQLite | 사용자·브랜치·세션·버전·작업·이벤트 저장 |
| 파일 저장소 | 버전 파일, 편집 작업본, AI 임시 작업본, 첨부파일, Harness 실행 기록 |
| systemd | 웹 서버와 Worker의 별도 실행·종료·재시작 |

서버는 OpenRouter API로 `deepseek/deepseek-v4.1-flash-1017`만 호출한다. 키는 서버 환경에서 공급한다. 브라우저가 종료되어도 Worker는 실행 중인 작업을 계속 처리하며, 사용자는 재접속해 결과를 확인한다.

## 배포 전 확인

1. 구현 B1단계에서 웹과 Worker의 개별 실행·빌드·종료를 확인한다.
2. 구현 B2단계에서 ARM64 환경의 rhwp 문서 처리, Harness, SQLite 모듈을 검증한다.
3. HWP·HWPX 각각의 열기→직접 편집 또는 AI 수정→저장→다시 열기를 확인한다.
4. 운영 도메인과 HTTPS 유입 경로를 확정하고 프록시의 업로드·SSE 연결 설정을 확인한다.
5. 실제 부하를 측정해 전체 동시 AI 작업 수, 파일 크기와 작업 시간 제한을 정한다.

특정 사용자가 여러 문서에서 AI 작업을 요청할 수 있도록 하고, 서버 자원에 맞는 전체 동시 실행 한도를 둔다. 단일 브랜치의 AI 쓰기 작업은 순서대로 실행하며 직접 편집과의 충돌은 결과 선택으로 처리한다.

## 데이터 보관과 복구

운영 데이터 루트 아래에 `app.sqlite`, `versions/`, `workspaces/`, `jobs/`, `attachments/`, `harness/`를 둔다. 초기 개발 기본 경로는 프로젝트의 `data/`이며 운영 경로는 서버 설정으로 지정한다.

이력 보관은 기본 30일로 설정하고 관리자가 변경할 수 있게 한다. 대표 버전, 브랜치 최신 버전, 진행 중 작업의 기준 파일과 미선택 AI 결과 등 필요한 참조는 보호한다. 사용자의 대화 세션 단위 복원과 운영 백업은 각각 제공한다.

초기 백업은 수동으로 수행한다. 변경 요청을 막고 Worker를 안전하게 정지한 상태에서 일관된 DB와 참조 파일을 함께 백업한다. 빈 데이터 경로에 복원해 로그인, 문서 열기, 브랜치·버전 관계를 확인한다. API 키 등 비밀 설정의 복구 방법도 실제 운영 절차에 기록한다.

## 구현 B10단계에서 완성할 파일

- `Caddyfile`: 도메인·HTTPS·프록시 설정.
- `systemd/deepet-web.service`, `systemd/deepet-worker.service`: 웹·Worker 실행 설정.
- `../scripts/backup.ts`, `../scripts/restore.ts`: 일관된 백업과 복원 명령.
- 이 문서: 검증한 설치·업데이트·재시작·백업·복원 명령과 운영 결과.

설정과 스크립트의 들여쓰기는 공백 4개를 사용한다. Git 추적 대상과 제외 기준은 [소스 관리 문서](../docs/git.md)를 따른다.
